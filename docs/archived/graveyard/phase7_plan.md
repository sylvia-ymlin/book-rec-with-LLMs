## 三、核心技术模块

### 3.1 多路召回 (Multi-Channel Recall)

| 召回通道             | 算法                               | 候选数 | 特点         |
| -------------------- | ---------------------------------- | ------ | ------------ |
| **ItemCF**     | 书籍共评相似度 (位置权重+时间权重) | 50     | 协同过滤经典 |
| **UserCF**     | 用户相似度 (Jaccard + 活跃度惩罚)  | 50     | 相似用户推荐 |
| **Embedding**  | ChromaDB 向量检索                  | 50     | 语义相似     |
| **Popularity** | 评分热度排行                       | 20     | 冷启动兜底   |
| **YoutubeDNN** | 双塔 User-Item 内积                | 50     | 深度学习召回 |

**ItemCF 核心公式** (迁移自 news-recommendation):

```python
# 位置权重: 相邻评分的书更相关
loc_weight = loc_alpha * (0.9 ** (|loc1 - loc2| - 1))

# 时间权重: 评分时间接近权重更高  
time_weight = exp(0.7 ** |t1 - t2|)

# 评分权重: 高分书之间的共现更重要
rating_weight = (r1 + r2) / 10

# 归一化: 避免热门书主导
sim[i][j] = Σ(loc × time × rating) / sqrt(cnt[i] × cnt[j])
```

### 3.2 YoutubeDNN 双塔模型

```
┌─────────────────────┐     ┌─────────────────────┐
│     User Tower      │     │     Item Tower      │
├─────────────────────┤     ├─────────────────────┤
│ Input:              │     │ Input:              │
│ • 历史评分书籍Emb   │     │ • 书籍描述 Embedding │
│ • 评分序列 (加权)   │     │ • 书籍类型 One-hot  │
│ • 用户统计特征      │     │ • 书籍热度特征      │
├─────────────────────┤     ├─────────────────────┤
│ MLP:                │     │ MLP:                │
│ Dense(256) → ReLU   │     │ Dense(256) → ReLU   │
│ Dense(128) → ReLU   │     │ Dense(128) → ReLU   │
│ Dense(64)           │     │ Dense(64)           │
└──────────┬──────────┘     └──────────┬──────────┘
           │                           │
           └───────────┬───────────────┘
                       ▼
              dot(user_vec, item_vec)
                       ↓
              Sigmoid → P(click)
```

### 3.3 特征工程

| 特征类型           | 具体特征                                  | 维度 |
| ------------------ | ----------------------------------------- | ---- |
| **用户特征** |                                           |      |
|                    | 评分书籍数量                              | 1    |

|                    | 评分方差 (挑剔度)                         | 1    |

| **书籍特征** |                                           |      |
|                    | 评分数量                                  | 1    |

|                    | 类型 ID                                   | 1    |

## 五、数据一致性设计决策

### RAG vs 推荐系统的数据关系

```
┌─────────────────────────────────────────────────────────────────┐
│  RAG 系统 (搜索/问答)                                           │
│  - chroma_db: 221,998 书籍 (全量索引)                           │
│  - chroma_chunks: 788,174 评论句子                              │
│  - 来源: books_data.csv + Books_rating.csv (全部)              │
└─────────────────────────────────────────────────────────────────┘
                         ↑ 推荐结果的书 
                         ↓ 可以在这里查详情
┌─────────────────────────────────────────────────────────────────┐
│  推荐系统 (个性化)                                              │
│  - 书籍: 133,816 (有评分交互的)                                │
│  - 用户: 167,968 (活跃用户)                                    │
│  - 来源: Books_rating.csv (筛选活跃用户)                       │
└─────────────────────────────────────────────────────────────────┘
```

### 设计决策

| 问题                               | 决策      | 原因                     |
| ---------------------------------- | --------- | ------------------------ |
| **两系统数据是否需要一致？** | ❌ 不需要 | 职责不同                 |
| **RAG 需要全量书籍吗？**     | ✅ 是     | 用户可能搜索任何书       |
| **推荐需要全量用户吗？**     | ❌ 否     | 只有活跃用户才有足够历史 |
| **推荐的书能在RAG查到吗？**  | ✅ 100%   | 已验证：133,816/133,816  |

### 数据流

```
用户请求 "为我推荐"
        ↓
推荐系统 (133K书籍 × 167K用户)
        ↓
返回 Top-5 ISBN
        ↓
RAG系统 (221K书籍索引)
        ↓
补充书籍详情 + 可对话
```

**结论**: 两个系统可以独立维护，只要推荐结果的ISBN在RAG索引中存在即可。
